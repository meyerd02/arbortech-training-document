Arbortech – How the Product Page Works

One product template powers every tool and accessory on the store. This guide explains what shoppers see on a product page (PDP), how the “Configure your order” area prices things, and which switches in Shopify admin control each behaviour — no code required.

On this page

1. Anatomy of the page 2. Variants & markets 3. Attachments & Accessories 4. Bundle with 5. The order summary 6. Context switching 7. Regional editing 8. What you control in admin 9. Special cases 10. Guardrails

1. Anatomy of the page

Every product uses the same template. The buy area (right of the gallery) assembles itself from the product’s data — sections that have nothing to show simply don’t render.

2. Variants & markets

Products with more than one variant show pill-style pickers for each choice the shopper should make (e.g. Voltage). Some variant dimensions are market-routed and never shown: a shopper in Australia silently gets the AU/UK/EU stock unit, a US shopper the US/Canada one. Which markets see which values is data-driven (admin-editable “market option rules”), not code.

  • Prices always render with their currency ($429.00 AUD) and follow the shopper’s market.
  • An accessory with no purchasable variant in the current market simply doesn’t appear.
  • Everything else that differs per region — availability, price, wording — is covered in §7 Regional editing.

3. Attachments & Accessories

Compatible add-ons for the tool being viewed. Each row is a full-width tick box — ticking adds it to the order as its own cart line at its own price.

  • Rows are vertical-aware: if the product has an accessory list for the shopper’s current context (say, masonry), that list is shown instead of the default (see §6).
  • Spare parts never appear here — anything categorised spares-consumables is excluded from the PDP by design.

5. The order summary

The moment anything is ticked, a summary appears above Add to cart: each line at its listed value, one discount row, and the subtotal that will actually be charged. A worked example with real store data:

LineListed
PCU + TURBOPlane Bundle (replaced the tool)$619.00
Ball Gouge (accessory, ticked)$130.00
Discount−$28.50
Subtotal$720.50

The top-of-page price shows the main item only ($590.50 here — the bundle that replaced the tool); the summary owns the full total. Untick everything and the page returns to the plain product price.

6. Context switching (verticals)

The same product page adapts to the shopper’s journey. A TURBOPlane reached from the Woodworking range reads as a woodworking product; the identical URL reached from a masonry route can show masonry-specific copy, imagery and accessories.

7. Regional editing: price, availability & wording per market

There is one product record, shared by every market. You never “switch region” on the product form itself — the base form is the default for everyone. Regional differences are layers applied on top of that one record, and each kind of difference has its own home in admin:

“I want to…” — which tool answers it

Task (from the client walkthrough)Where it lives
Stop selling a product in one market (e.g. hide from Germany)On the product: the Markets / Catalogs card — untick that market. The product stays live everywhere else.
Change the price for one market onlySettings → Markets → (market) → catalog price list. The product form’s price field is the base price for all markets.
Put a product “out of stock”Stock is global — one shared pool, there is no per-market inventory. Set the quantity to 0 (out of stock everywhere) or use the catalog toggle above to withdraw it from one market.
Translate the page into GermanTranslate & Adapt app → language German → the product → fill the German columns. The theme picks it up automatically on /de-de.
Reword the description for the US (same language, different copy)Translate & Adapt app → switch the selector from a language to a market (US / Canada / UK) → override just the fields you want. This is “adapt” — per-market English, no translation involved.
Regional story panels / description leads in the custom sectionsProduct metafields — the …_us / _au / _ca / _de variants (see §8). These feed the bespoke Arbortech sections rather than Shopify’s standard fields.

Which wording wins when both are set

For content the custom sections render (like the description lead): a per-market metafield beats a Translate & Adapt value, which beats the base content. If a regional edit doesn’t seem to show, check whether a market metafield is overriding it before re-editing in Translate & Adapt.

Two things to know before regional edits

  • US pricing currently follows the AUD price. The USD price list can’t take effect until USD is enabled as a presentment currency — until then a US-only price change won’t behave as expected.
  • Adapted copy goes stale silently. Once a market override exists, editing the base description does not update that market. After a base rewrite, skim Translate & Adapt for markets still carrying old wording.

8. What you control in admin

Everything above is driven by product data — mostly metafields on the product, editable in Shopify admin. The load-bearing ones:

Setting (metafield)What it does
arbortech.related_accessoriesDefault Attachments & Accessories list for the tool.
arbortech.vertical_woodworking / _masonry / _landscapingPer-vertical content pack: description lead, image order, video, and its own accessories list.
arbortech.primary_verticalFallback vertical when the shopper arrives without a journey.
arbt.related_bundlesWhich bundle products appear under “Bundle with”.
arbortech.bundle_components (on the bundle)The SKUs inside the bundle — this is how the page knows a bundle contains the tool.
arbortech.bundle_includes (on the bundle)Accessory products the bundle contains — used to avoid double-charging.
Variant compare-at price (on the bundle)The “total value”. Compare-at above price = struck price + “Save $X”. No compare-at, no saving shown.
arbt.addon_media_mapMaps an accessory/bundle to a gallery photo of the tool with it — ticking scrolls the gallery there.
arbt.addon_category (on the accessory)spares-consumables keeps an item off the PDP entirely.
arbt.pre_orderSwitches the buy button into pre-order messaging.

How bundle prices are set

Bundle price = what the shopper pays for the whole package. Bundle compare-at = the sum of the parts bought separately. The standing policy is the tool at full price plus 15% off the accessories (the bundle_discount_percent setting on each bundle); where the legacy site sells the identical kit, its live price is used instead. A repricing helper (tools/shopify/set-bundle-compare-at.mjs) applies these rules and writes a report — never hand-type a bundle price below the price of its most expensive component.

9. Special cases

  • MG1000 and ALLSAW AS200X use a bespoke family configurator (Tool Setup choices like Skin vs Battery Kit). Their setup choice owns the variant; everything in this guide still applies around it.
  • MG1000 packs (Woodworking / Restoration) are discounted in the cart by an automatic merge — their PDP tiles deliberately show no “Save” badge; the saving appears at cart level.
  • Bundles show only on power tools. An accessory’s own page never offers bundles, even if data exists.
  • Sold-out bundles grey out but stay visible with a “Sold out” note — availability is computed from component stock.

10. Guardrails

Before you change product data

  • Don’t price a bundle below its biggest component. Tool-inclusive bundles replace the tool in the cart — an under-priced bundle sells the tool at that price.
  • Don’t set a compare-at below the price. It will simply never show; the page refuses to display negative savings.
  • Don’t add spare parts to related_accessories expecting them to appear — they’re filtered out by category everywhere on the PDP.
  • Keep bundle component lists truthful. The substitution and no-double-charging logic trusts bundle_components / bundle_includes; a wrong list means wrong carts.
  • Vertical content is optional but all-or-nothing per block — a vertical with its own accessory list fully replaces the default list in that context.
