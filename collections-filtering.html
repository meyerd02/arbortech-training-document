Arbortech – Collections & Filtering

How a product's tags and metafields decide which listing it appears in, which sidebar options are already ticked, and which filters can quietly hide it. Everything here is done from Shopify admin — no code required.

On this page

1. The two axes

Every listing on the store is built from two axes, and they do different jobs.

Vertical — woodworking, masonry, landscaping. This only narrows the product set. It never changes which filters exist.

By Product (the bucket) — power-tools, attachments-accessories, spare-parts-consumables. This also narrows the product set. Application Type, Compatible With and Associated Tool stay under this group on every listing; empty values disable rather than hiding the group.

Click a filter on and off. Checking a second box in the same set is additive. View all is the only exclusive control — it unclicks the rest of that set. Filter clicks stay on the page you are on; they do not send you to a different collection.

Stored twice, on purpose

On a product, both axes are tags — that is what the smart-collection rules match on. On a collection, they are the metafields arbt.vertical and arbt.bucket — that is what tells the sidebar which checkbox to pre-tick. The tags are the truth; the metafields describe the page.

2. Product fields → sidebar

Six fields feed three outcomes: which listings a product appears in, which sidebar checkboxes are pre-ticked, and which values inside the (always-present) metafield groups are available.

4. Which filters appear where

Every filterable listing uses the same sidebar. Two additive checkbox groups are Arbortech's own (View all unclicks the rest of that set; everything else stacks); three checkbox groups are Shopify's native metafield filters, nested under By product, and those also allow more than one value. Search is the exception: it has the three metafields and no Product categories / By product groups.

Three things this table is telling you

  • Tool family sits under Power Tools and stays there. The nine families — Mini Grinder, ALLSAW, AS200X, BA200X, AS175, Power Carving Unit, Power Chisel, TurboPlane, Standard Angle Grinder — do not remount when you click around. A family with no products in the current view is disabled.
  • Search deliberately skips the taxonomy groups. The three metafield filters appear as top-level accordions there. Product categories and By product are collection-page controls.
  • Product Type is retired everywhere, search included. By product replaced it. Switching it back on in Search & Discovery will not bring it back.

Two switches, not one

A metafield filter has to be switched on in the Search & Discovery app to exist at all. The theme always mounts Application Type, Compatible With and Associated Tool under By product; turning one off in the app is what removes it, not the collection you landed on.

5. Three things that catch people out

A blank field hides the product

An empty filter value is not neutral. A spare part with no Associated Tool / Model lists normally — until a shopper ticks any box in that group, at which point it disappears from the results. The fixed choice list prevents typos; it cannot force the field to be filled in.

Active is not the same as visible

Product and collection status and sales-channel publication are separate switches. An Active collection that is not published to the Online Store returns a “page not found” while still looking perfectly healthy in admin. Check the sales-channel list, not the status label.

Pick, never type

All three filter metafields carry a fixed list of choices, so admin shows a dropdown rather than a text box. That is what stopped two near-identical values splitting a single filter into two look-alike options. The trade-off: adding a brand-new value is a settings change, not a product edit, so it is not self-serve — ask Juicebox.

6. Changed recently

Worth knowing before you trust older notes

  • The masonry hub is titled Masonry & Trade and sits at masonry-and-trade. Its two sub-collections use masonry-and-trade-… web addresses; the underlying tag is masonry. Title, web address and tag are separate fields even when their wording now aligns — do not infer one from another.
  • Four listing templates, one listing chrome. Woodworking, Masonry & Trade and Landscaping each have their own layout so extra unique sections can be added in the theme editor on that vertical only. Title, image and intro still come from the collection in admin — do not paste the same paragraph into a theme section. Every other filterable collection uses Default collection. Spare Parts, Blades & Accessories is the accessory hub (no filters).
  • The sidebar no longer rebuilds when you click a filter. Product categories and By product stay put. Application Type, Compatible With and Associated Tool sit under By product on every listing. Click a filter on and off; View all unclicks the rest of that set; everything else is additive. Clicks stay on the collection you opened — they do not send you to Shop All.
  • Filter labels follow the collection title, so the Product categories options read Woodworking / Masonry & Trade / Landscaping. Rename a hub collection and you rename a filter option. Attachments & Accessories has no hub collection of its own, so its label is fixed in the theme.
  • The retired accessories tag is present again, on exactly the same products as attachments-accessories with no difference between them. Nothing reads it — no collection rule, no filter — so it is harmless today. It is also the same shape as the fault that once split one filter across two look-alike options: edit one tag without the other and they will drift apart.
  • Spare Parts, Blades & Accessories is published to the Online Store now. Older notes record it returning “page not found”; that is no longer true.

7. Where to change what

Which products are in a listing
The product's tags — or the collection's rule, if the rule is what is wrong. Products · Collections
What a filter option is called
The title of the hub collection for that value. It also translates through Translate & Adapt, unlike a label fixed in the theme.
Which values a filter offers
The metafield's list of choices, under Settings → Custom data → Products. Adding a value here is a settings change, not a product edit.
Which filters exist at all
The Search & Discovery app, under Apps. Turning one off removes it from every page, search included.
Which layout a collection uses
The Theme template selector on the collection page in admin. The three vertical hubs use their named layouts (Woodworking, Masonry & Trade, Landscaping). Other filterable listings use Default collection. Switching a collection onto the accessory hub layout removes its filters entirely.
Which checkbox is pre-ticked on a page
The collection's own arbt.vertical and arbt.bucket metafields, edited on the collection in admin.

8. Triage

What you're seeingWhere to look first
A filter group is missing from a pageThe page is on the accessory hub layout (no filters), or the filter is switched off in Search & Discovery. The three vertical hubs and Default collection all show the same filter groups.
A checkbox isn't pre-ticked when it should beThe collection is missing arbt.vertical or arbt.bucket. Nothing errors when it is absent — the sidebar just sits neutral.
A product disappears when a box is tickedIt has no value for that filter. Fill the field in on the product.
Two filter options look identicalTwo near-identical values in the choice list, or a stale tag sitting alongside its replacement. Merge them in Settings → Custom data.
The page says “not found” but admin looks fineNot published to the Online Store sales channel.
A filter label reads wrong after a renameExpected — labels follow hub collection titles. Retitle the hub, or accept the new wording.
